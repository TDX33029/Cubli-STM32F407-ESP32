## 一、LQR 控制算法复查结论与修复（重点）

### 1.1 总体结论
另一 Agent 新实现的总体架构（卡尔曼姿态融合 + 1D 边沿平衡 4 态 LQR + 3D 顶点解耦 LQR +
跌倒保护状态机）**结构合理、主体正确**，但存在 **1 处必然失效的符号错误**、
**2 处结构性缺陷** 和 **2 处逻辑不一致**，已全部修复。

### 1.2 修复一（关键）：动量轮转速反馈与积分项符号错误

**位置**：`Hardware/lqr_balance.c` 边沿平衡模式控制律。

**原实现**：
```c
u = K_theta*err + K_dtheta*dtheta + K_w*w_wheel + K_i*wheel_int;
if (sensor_direction[m] < 0) u = -u;      // 整体翻转
```

**为什么错（物理推导）**：
反作用轮摆 (Reaction Wheel Pendulum) 线性化动力学中，控制量 u（电机力矩）进入两个通道的
符号**相反**：
- 机体通道：`θ̈ = a·θ − b₁·u`（a>0，b₁>0）—— 反作用力矩帮助机体纠偏；
- 飞轮通道：`ω̇ ≈ b₂·u`（b₂>0）—— 力矩直接加速飞轮。

因此正确的控制律（取"正电压→飞轮正转、倾角正方向与机架映射一致"的约定）为：
```
u = +K_theta·θ + K_dtheta·θ̇ − K_w·ω − K_i·∫ω     (所有 K > 0)
```
- 倾角通道取 **+**：正倾角需正飞轮力矩，其反作用力矩把机体推回；
- 飞轮转速通道取 **−**：转速偏高时指令必须**反向制动**把飞轮拉回零速（退饱和）。

原实现中 K_w、K_i 项为 **+号**，且随 `sensor_direction` 被**再次整体翻转**——
这两项构成对飞轮转速的**正反馈**：飞轮稍有一点点转速就会越转越快，
直至电压饱和、退饱和机制完全失效，动量轮"飞车"。
此错误在**任何安装方向约定下都必然错误**（可严格证明），故必须修复。

**修复后**（注意：`shaft_velocity[]` 已是传感坐标系速度，绝不能再随 sensor_direction 翻转）：
```c
float u_ang = K_theta*err + K_dtheta*dtheta;
if (sensor_direction[m] < 0) u_ang = -u_ang;          // 仅倾角通道随机架/旋向翻转
float u = u_ang - K_w*w_wheel - K_i*wheel_int[m];     // 飞轮通道固定负反馈
```
头文件 `lqr_balance.h` 中控制律注释同步更正。

### 1.3 修复二：3D 顶点平衡模式缺失退饱和通道

**位置**：`Hardware/lqr_balance.c` 顶点平衡分支。

**问题**：
1. `corner_gains[].K_i` 有初始值，但 Tx/Ty 计算中**从未使用积分项**；
2. `wheel_int[]` 在顶点模式下**从不积分**（飞轮转速长期残留不受控，与 1D 模式行为不一致）。

**修复**：补上 `wheel_int[0..2]` 的积分与限幅（±50 rad），并按 120° 几何映射
投影出虚拟轴积分量 `int_vx / int_vy`，以 **负号** 进入 Tx/Ty（与修复一同一符号约定）。

### 1.4 修复三：M3 边沿模式 P/D 项坐标不配对

**位置**：`Hardware/lqr_balance.c` 边沿模式 M3 分支。

**问题**：原实现 `theta = pitch`（X 轴倾角）但 `dtheta = gyro_z`（Z 轴角速度）——
LQR 的 P 项与 D 项作用于**不同坐标系的状态量**，不是合法的状态反馈，D 项会在
X 轴俯仰与 Z 轴偏航之间注入无关联能量，可能诱发振荡。

**修复**：改为 `theta = attitude.yaw, dtheta = gyro_rad[2]`（同一坐标的角度+角速度配对）。
注：yaw 由陀螺仪积分获得会缓慢漂移，Z 轴边沿模式本身为实验性调试模式（文档已注明），
正式平衡请使用 M1/M2 边沿或 3D 顶点模式。

### 1.5 修复四：使能后跳过捕获窗口直接满幅输出

**位置**：`LQR_Balance_Enable(true)`。

**问题**：已校准状态下使能平衡直接进入 `BAL_STATE_BALANCING`。若使能时机身倾角较大
（例如 10°），首拍即输出大矫正电压，捕获瞬间猛烈跳机。

**修复**：改为进入 `BAL_STATE_STANDBY`，由控制循环中既有的捕获逻辑
（倾角 < `capture_angle` 5° 才切入 BALANCING）完成安全捕获。
原代码本就实现了 STANDBY 捕获窗口逻辑，只是使能入口绕过了它。

### 1.6 复查确认无误的部分（未改动）
- 卡尔曼滤波器实现（预测/增益/协方差更新）为标准一阶姿态融合，正确；
- `LQR_Attitude_Update` 的零偏校准流程（200 样本均值）正确；
- 加速度计倾角公式与陀螺轴的配对（pitch↔Gx, roll↔Gy）在小角度下自洽（符号细节
  依赖 IMU 贴装方向，硬件联调时如方向相反可通过调 `theta_0`/镜像处理，不属代码错误）；
- 输出限幅、`voltage_limit` 联动、跌倒保护阈值（15°）与恢复（5°）逻辑正确；
- 顶点模式 120° 逆变换与正映射自洽（含 1.5 倍标量因子，可吸收进增益）；
- 200Hz 主循环调度、`loopFOC` 后置 `setPhaseVoltage` 的输出时序正确（本移植版
  `loopFOC` 只做传感更新与电角度解算，不重复输出相电压）。

## 二、ESP32 无线链路（新增硬件适配）

### 2.1 方案选型：WiFi TCP（而非 BLE）
- **吞吐**：$TELE 遥测帧约 250 字节 × 25Hz ≈ 6.3 KB/s，BLE 4.2 GATT 通知吞吐
  通常 <2 KB/s 且分包抖动大；WiFi 轻松承载并有富余；
- **上位机改动**：TCP 字节流与串口字节流语义完全一致，解析层零改动；
- **可达性**：AP 热点直连模式无需路由器即可用手机/笔记本连接；
- BLE 仅在极低速率、省电场景有优势，本场景无需。

### 2.2 硬件连线（依据网表 `Netlist_MB_Schematic_2026-10-07.net`）
| 信号 | F407 引脚 | ESP32 引脚 | 说明 |
|:--|:--|:--|:--|
| UART1-TX | PA9 (USART1_TX) | U8-11 **IO26** | F407 发送 → ESP32 接收 |
| UART1-RX | PA10 (USART1_RX) | U8-10 **IO25** | ESP32 发送 → F407 接收 |

波特率 **115200-8-N-1**，两侧一致。

### 2.3 F407 侧改动
| 文件 | 改动 |
|:--|:--|
| `Core/Src/usart.c` | 新增 `MX_USART1_UART_Init()`（PA9/PA10 AF7）、`huart1` 句柄与 MspInit 分支（时钟/GPIO/NVIC）；`fputc` 与收发中断改为 **公共链路函数** `USART_Link_IRQHandler()`，经宏 `DEBUG_LINK_USART`（默认 1=USART1 无线，2=USART2 有线后备）作用于选定串口；未选中的串口不使能 RX 中断，避免中断风暴 |
| `Core/Inc/usart.h` | 新增 `huart1`、`MX_USART1_UART_Init()`、`USART_Link_IRQHandler()` 声明 |
| `Core/Src/stm32f4xx_it.c` | 新增 `USART1_IRQHandler`；`USART2_IRQHandler` 同步改调公共链路函数（后备可用） |
| `Core/Src/main.c` | 外设初始化序列中调用 `MX_USART1_UART_Init()` |

- 原环形缓冲异步发送机制（零阻塞 printf）完整保留，仅物理出口切换；
- `$TELE` 遥测帧格式、全部命令（TEST/BAL/BMODE/LQR/CAL_IMU/…）**一字未改**，

## 四、MT6701 编码器第二种读取方式：定时器硬件正交解码（宏开关）

### 4.1 设计
- **不破坏原方法**：三路 I2C 绝对式读取原样保留；新增统一抽象层
  `Hardware/enc_quad.c/h`，上层代码一律经由 `ENC_GetAngle(idx, &raw, &deg)` 读取；
- **宏定义编译期选择，上电后不再切换**：
  ```c
  // Hardware/enc_quad.h
  #define ENC_USE_HW_QUAD   0   /* 0=I2C绝对式(原方法,默认)  1=定时器硬件正交解码(新方法) */
  ```
- 两种方式都在固件中编译存在（`ENC_I2C_GetAngle` / `ENC_Quad_GetAngle`），
  仅路由不同；切宏后需重新编译烧录。

### 4.2 引脚对照表（依据网表）
| 电机 | 编码器座 | A 相 | B 相 | 定时器 | AF |
|:--|:--|:--|:--|:--|:--|
| M1 | ABZ-1 | PA5 (TIM2_CH1) | PB3 (TIM2_CH2) | **TIM2** | AF1 |
| M2 | ABZ-2 | PA0 (TIM5_CH1) | PA1 (TIM5_CH2) | **TIM5** | AF2 |
| M3 | ABZ-3 | PC6 (TIM8_CH1) | PC7 (TIM8_CH2) | **TIM8** | AF3 |

（网表节点：`M1-A=PA5/ABZ-1-1, M1-B=PB3/ABZ-1-2, M2-A=PA0, M2-B=PA1, M3-A=PC6, M3-B=PC7`）

### 4.3 资源冲突处理（重要）
- **TIM5 原为 `micros()` 微秒时基**（32 位自由计数器），但 M2 的 PA0/PA1 只能映射到
  TIM2/TIM5，而 TIM2 必须给 M1（PA5/PB3 无 TIM5 复用）。因此 HW_QUAD 模式下
  **micros() 迁移到 TIM7**：16 位 1MHz + 更新中断维护高 16 位扩展
  （`timer.c` 中 `TIM5_Micros_Init()` 按宏内部改配 TIM7，`micros()` 输出的
  uint32 回绕特性与原实现完全一致，`(uint32_t)(now-last)` 差值算法无需任何改动）；
- I2C 模式（宏=0）下完全维持原有 TIM5 时基，零影响；
- PB3 上电默认为 JTAG TDO (AF0)，配置为 AF1 后即作 TIM2_CH2；SWD 调试（PA13/PA14）不受影响，仅 SWO 跟踪输出不可用。

### 4.4 实现细节
- 定时器配置为**编码器模式 3**（TI1&TI2 双边沿 ×4 计数），ARR=0xFFFF，
  IC 滤波 N=8 抑制毛刺，寄存器级初始化（不依赖 CubeMX 重生成）；
- 每圈计数 `ENC_QUAD_COUNTS_PER_REV`（默认 **1024**，即 MT6701 ABZ 每圈
  256 线 ×4 解码）——**若实际 ABZ 配置不同，仅需修改该宏**；
- 速度/多圈累加/低通滤波逻辑复用 `updateSensor()` 既有管线
  （最短角差解包、14-bit→CPR 分辨率自适应换算、12ms 一阶低通）；
- 电机↔传感器映射 `motor_sensor_map[]`、旋向自学习（TEST 自检）、电角度对齐（ALIGN）
  全部兼容两种方式（相关调用点已统一接入 `ENC_GetAngle`）。

### 4.5 精度权衡说明
14-bit I2C 绝对式（0.022°/LSB）分辨率显著高于 ×4 后 1024 counts（0.35°/LSB），
高速时定时器方式每 5ms 采样窗口内计数跳动更大，依赖低通滤波平滑；
低速下 1 count ≈ 1.2 rad/s 的量化跳变也更明显。**追求平衡控制精细度建议保持 I2C 方式（默认）**；
定时器方式的优势是零 I2C 总线占用（消除三总线轮询的阻塞抖动）与更低 CPU 开销。

### 4.6 本轮涉及的编码器调用点统一
`Core/Src/main.c`（上电自检、HALL/ENC 查询、TEST 自检、极对数测量）、
`SimpleFOC/FOCMotor.c`（updateSensor）、`SimpleFOC/BLDCMotor.c`（对齐前在线检查）
全部改为经 `ENC_GetAngle` 访问（宏=0 时路由到原 I2C 函数，行为不变）。

## 七、遗留注意事项（硬件联调时确认）
1. `ENC_QUAD_COUNTS_PER_REV=1024` 需与 MT6701 实际 ABZ 配置核对；
2. 倾角通道符号与 IMU/电机贴装方向相关，现场如有偏差通过 `ZERO`/`BMODE` 校准，
   必要时在 `lqr_balance.c` 倾角通道按轴加符号宏；
3. 3D 顶点模式的 IMU→虚拟轴映射同样依赖贴装，建议先在 M1/M2 边沿模式验证；
4. ESP32 固件需在 `main.cpp` 顶部配置区填入实际 WiFi 凭据（STA 模式），
   不配置也可直接用 AP 热点模式（192.168.4.1:3333）；
5. Z 轴边沿（M3）模式为实验性：yaw 积分漂移会限制长时间使用。
