## 一、硬件发热保护事故的根本原因深度复盘

### 1.1 事故现象
在串口执行 `ALIGN`（电角度对齐）后不久，电池和 3 个无刷电机发生严重异常发热，并最终触发了电池 BMS 保护板的过流/过温自锁断电保护。

### 1.2 底层代码 Bug 与发热机理剖析
经深入排查固件驱动代码，导致线圈和芯片过热烧毁的核心原因为 **固件底层缺少“开环零速切断保护”与“校准后未释放硬件使能”产生的恶性叠加**：

1. **Bug ①：校准完成后未失能 DRV8313 驱动芯片**  
   原 `Motor_alignSensor()` 在执行电角度寻零时，通过 `set_motor_enable(motor + 1, 1)` 打开了对应的 DRV8313 硬件使能引脚。校准结束后，代码**未关闭使能**，导致三路电机的驱动硬件全部处于通电导通状态（`EN: 111`）。
2. **Bug ②：开环调速函数在零速时持续输出 6.0V 全幅直流堵转电压（致命点）**  
   固件上电后默认处于开环速度控制模式（`MODE 0`），目标速度为 0。在原 `SimpleFOC/BLDCMotor.c` 的 `velocityOpenloop()` 中：
   ```c
   float velocityOpenloop(float target_velocity, int motor)
   {
       ...
       // 致命缺陷：完全没有检查 target_velocity 是否为 0！
       open_loop_angle[motor] = _normalizeAngle(open_loop_angle[motor] + target_velocity * Ts);
       setPhaseVoltage(voltage_limit, 0, _normalizeAngle(open_loop_angle[motor] * (float)pole_pairs), motor);
       return voltage_limit;
   }
   ```
   当 `target_velocity == 0` 时，角度积分停止，但它**依然将 `voltage_limit`（原固件配置为 6.0V）持续施加在电机的定子线圈上**！
3. **发热与过流计算**：  
   本项目采用的 2804 云台无刷电机相电阻仅约为 $R \approx 10\,\Omega$。在直流静止施加 6.0V 电压下，电机内部无任何反电动势抵消，单相静态电流高达：
   $$I_{\text{DC}} = \frac{U}{R} = \frac{6.0\text{V}}{10\,\Omega} = 0.6\text{A}$$
   三相电机同时静止堵转通电，整机在静止状态下持续产生高耗散功率：
   $$P_{\text{loss}} \approx 3 \times (0.6\text{A} \times 6.0\text{V}) \approx 10.8\text{W}$$
   对于无散热风扇的小体积 2804 电机线圈与 DRV8313 芯片，11W 的纯电阻集中发热在数十秒内就会将线圈升温至 80℃ 以上，且 3S 锂电池持续大电流放电，最终触发了电池保护板自锁保护。

## 二、回答用户核心疑问：限压过低是否会影响速度变化效率？

> **用户关切**：“限压调这么低会不会影响速度变化效率？cubli又有频繁的速度和方向变化。”

### 2.1 结论：单纯机械式“全局压低限压”绝对不可取！
**您的判断完全正确！**  
Cubli 动量轮平衡机器人依赖反作用轮的角加速度产生机体姿态恢复力矩：
$$T_{\text{wheel}} = J_{\text{wheel}} \cdot \dot{\omega} = K_t \cdot I_q \propto U_q$$
在频繁的速度切换、极速正反转制动以及边缘起跳（Jump-up）冲击阶段，电机必须能够输出**最大爆发力矩**。如果为了安全简单粗暴地将全局相电压上限固定在 2.0V，则最大加速力矩被削减了 66%，且最高空载转速受反电势限制会被严重压缩在 30 rad/s 以内，彻底丧失 Cubli 所需的高动态爆发性能。

### 2.2 正确的工程解决方案：“动态全压爆发 + 静态硬关断 + 堵转超时保护”
发热的根源**绝不是电机在高速旋转或快速换向时的相电压**（因为高速旋转时电机内部存在反电势 $E_b = K_e \omega$ 抵消端电压，稳态运行电流仅 $0.1\sim 0.2\text{A}$，发热极小），**发热的唯一根源是静止与堵转状态下的纯直流耗散**！

因此，本次重构建立了三维立体硬件防护架构：
1. **动态/换向阶段释放充沛相电压**：  
   默认动态相电压上限设置为 **`voltage_limit = 5.0V`**（并允许通过串口 `U <val>` 动态调至 6.8V），保障 Cubli 在频繁换向、急加减速时拥有毫秒级打满的极限推力；
2. **零速关断与闭环减速**：
   开环目标斜坡降到 $|v| < 0.05\text{ rad/s}$ 后输出零矢量。闭环在目标和实测速度都接近零时才关断，减速阶段仍由速度环输出反向制动力矩，避免原先目标一归零就失去主动制动；
3. **堵转过载超时降压保护（Stall Timeout Protection）**：  
   在闭环控制中加入状态机监测：如果输出电压持续接近上限，但实测转速与目标转速误差持续 $> 3\text{ rad/s}$ 超过 **800ms**（判定发生机械卡死或外力死卡），固件自动将该电机的输出限幅压制到安全保压阈值（1.8V），保护线圈不烧损；
4. **校准对齐后自动失能（Align Safe Disarm）**：  
   电角度自动校准电压由 2.8V 下调至 **1.8V**（实测已完全足够磁极吸合），且校准全部结束后强制执行 `set_motor_enable(0, 0)` 切断硬件驱动使能，进入休眠待机状态。

## 三、极低速丝滑旋转（消除卡顿）与高动态调速算法重构

### 3.1 原固件在极低速下严重“卡顿”（与摩擦力无关）的根本原因
原固件在闭环调速低速区（$|v| \le 3.0\text{ rad/s}$）错误地引入了“虚拟弹簧摆”公式：
```c
uq_sync = voltage_limit * sinf(delta_el);
```
- 该算法试图根据转子当前电角度与虚拟目标的相位差 $\delta$ 施加恢复力矩；
- 当电机低速运转时，转子只要因编码器采样量化稍有超前（$\delta < 0$），相电压立刻**翻转为负向全力反抽刹车**；转子一旦落后（$\delta > 0$），相电压又**猛烈正向踢一脚**；
- 这种在零点附近的频繁正负来回反打，导致电机在极低速下形成未阻尼的极限环高频颤振（Limit Cycle Oscillation），表现出强烈的“每走几度就猛烈卡顿抽搐一次”的齿轮打齿感。

### 3.2 极低速丝滑旋转算法实现（库仑摩擦前馈 + 反电势解耦）
要实现钟表机械般均匀顺滑的极低速旋转（0.2 ~ 3.0 rad/s），核心在于：**推进力矩必须始终平滑向前，绝不在零误差附近来回反向反打！**

新架构算法设计：
$$U_q = U_{\text{coulomb}} \cdot \text{sign}(v_{\text{target}}) + K_{\text{bemf}} \cdot v_{\text{target}} + \text{PID}(v_{\text{target}} - v_{\text{actual}})$$
1. **齿槽与摩擦偏置前馈 ($U_{\text{coulomb}} = 0.45\text{V}$)**：  
   在电机旋转方向上恒定注入微小偏置电压，刚好抵消定子铁芯齿槽转矩的卡顿门槛（Detent Torque），使转子在极低速下仿佛“悬浮滑动”；
2. **反电势前馈 ($K_{\text{bemf}} = 0.045\text{ V/(rad/s)}$)**：  
   随转速线性提供反电势补偿，使速度环 PID 仅需负责微弱外力扰动的补偿；
3. **平滑单向微调**：  
   库仑摩擦前馈使用平滑双曲正切过渡，并由速度 PID 修正低速误差。实际平滑度仍取决于电机、编码器噪声、安装和实测整定，不能仅由公式保证。

### 3.3 快速切换速度与方向变化的动态优化（Cubli 动作适配）
1. **条件积分抗饱和（Clamping Anti-Windup）**：  
   在 `PID_operator()` 中实现抗积分饱和机制：当输出已达到相电压限幅（如急反转时打满到 -5.0V），且当前误差方向依然同向时，**立即冻结积分器的累加**。这使得电机在以最大力矩完成减速反转并接近目标速度时，能以零超调瞬间精准锁定目标速度，杜绝了换向时深饱和带来的巨大转速冲顶和迟滞；
2. **解除微分项高频屏蔽**：  
   原代码要求计算周期大于 2ms 才计算微分项（导致主循环中 D 项永久失效为 0）。现放宽周期阈值至 $0.1\text{ms}$，并增加 $\pm 1.5\text{V}$ 的安全滤波限幅，使微调 D 增益能够真正对加减速冲击起到阻尼抗震作用；
3. **停转衰减响应提速**：  
   将停转判定时间由 50ms 缩短至 25ms，使电机在下发减速停转指令时能够以两倍的速度迅速收敛归零。

## 七、明日硬件维修完成后的安全上电与调试步骤建议

在您明天完成硬件维修（检查电机相线短路、更换损坏芯片或复位电池保护板）后，请严格遵循以下安全上电检查流程：

1. **静态电阻测试（断电状态）**：  
   使用万用表电阻档测量三轴电机相线之间（U-V, V-W, W-U）电阻，确认阻值均在 $10\,\Omega$ 左右且三相平衡，确认相线与地线（GND）无短路。
2. **限流稳压电源首次上电（推荐）**：  
   维修后首次上电，**强烈建议使用直流可调稳压电源**替代动力锂电池供电（设置电压 12.0V，**限流 0.5A**）。如果硬件发生意外短路，稳压电源会自动恒流降压，绝对不会烧毁元器件。
3. **固件烧录**：  
   使用 ST-Link 烧录最新编译的 `CubeMX.hex`。固件上电后所有电机驱动默认失能，静态电流接近 0。
4. **单电机逐步使能测试**：  
   打开上位机 `Software/main.py`：
   - 先执行 `ALIGN`（此时单轴校准完毕后会自动切断输出，不会持续通电）；
   - 点击切换到闭环调速模式；
   - 建议先从单电机使能开始（如勾选 M1 使能，关闭 M2/M3），设定微小速度（如 `+1.0 rad/s`）观察是否实现顺滑无卡顿旋转，再测试速度阶跃跳变（如 $+10 \to -10\text{ rad/s}$）。
