# F407 定时器硬件正交编码器检查与修复

本次检查结论：三路A/B引脚及TIM2/TIM5/TIM8四倍频选择正确，原默认固件并未启用该方法；原程序的分辨率定义、通用回绕处理和计数器可用性判断存在问题，现已修复并分别构建I2C版、正交版。

## 引脚与定时器

| 电机 | A相 | B相 | 定时器 | 复用 |
| --- | --- | --- | --- | --- |
| M1 | PA5 | PB3 | TIM2_CH1/CH2 | AF1 |
| M2 | PA0 | PA1 | TIM5_CH1/CH2 | AF2 |
| M3 | PC6 | PC7 | TIM8_CH1/CH2 | AF3 |

网表ABZ连接器1/2脚分别为A/B，3脚为3.3V，4脚为GND，5/6为连接器地/固定脚。未接入Z索引，软件实际上使用AB两相。PB3已配置AF1给TIM2，调试使用SWD（PA13/PA14），不要同时把PB3用于SWO/JTAG。

编码器模式为SMS=3，两路输入直接映射TI1/TI2，双边沿四倍频；输入捕获预分频为1，计数器PSC=0，IC1F/IC2F=3（内部时钟连续8次采样滤波）。TIM8作为输入计数器不需要PWM的MOE。

## 宏参数

`Cubli-ST/Hardware/enc_quad.h`：

```c
#define ENC_USE_HW_QUAD 0  /* 默认仍为I2C，改1则默认编译硬件正交 */
#define ENC_QUAD_PPR 1024U /* 四倍频前，每个A/B通道每机械圈脉冲数 */
```

按用户指定的标准模块先采用1024 PPR的配置假设，即**4096计数/机械圈**。若实际模块不同，改PPR后重新编译、烧录和电角度对齐；宏只修改STM32的计数换算，不会写MT6701的EEPROM。

也可按轴覆盖：

```c
#define ENC_QUAD_PPR_M1 1024U
#define ENC_QUAD_PPR_M2 1000U
#define ENC_QUAD_PPR_M3 512U
```

这些宏默认继承公共PPR，对应四倍频后4096/4000/2048计数/圈。有效PPR范围1～1024；零或超范围会编译报错。旧的公共`ENC_QUAD_COUNTS_PER_REV`覆盖仍兼容，其单位明确为四倍频后CPR，优先建议改PPR宏。

厂商资料将ABZ分辨率定义为脉冲/圈，范围1～1024，相关配置位为0x30[1:0]、0x31[7:0]；本工程没有读取/写入模块的该配置，不能从“标准模块”名称确定其实际EEPROM内容。[MagnTek MT6701数据手册](https://www.magntek.com.cn/upload/pdf/202312/MT6701_Rev.1.8_%E4%B8%AD%E6%96%87%E7%89%88.pdf)

## 修复内容

- 原代码固定ARR=65535，再将CNT对CPR取模。它对1024/4096这种能整除65536的CPR恰好连续，但例如1000 PPR→4000 CPR时，从0反转到65535会被误读成1535，产生角度跳变。现在每个定时器直接设置`ARR=该轴CPR-1`，正转与反转都在一机械圈边界回绕。
- 原1024“计数/圈”若用于1024 PPR模块，会造成角度、测速和电角度按四倍比例解释。现在PPR与CPR分开定义，统一在读取与FOC中使用传感器对应的CPR。
- 初始化显式清理PSC、DIER、输入捕获预分频/极性和旧状态；TIM8 RCR归零。调用前未初始化、定时器停转、模式/分频/ARR配置错误或计数越界时返回失败，不再无条件成功。
- I2C版调用QUAD初始化不会覆盖TIM5微秒时基。正交版TIM5专用于M2，微秒时基由TIM7提供；完善TIM7初始化时的中断清理，并验证待处理中断、65.536ms溢出及32位回绕。
- FOC的角度换算、测速量化门槛和停转超时采用对应传感器的CPR，支持三轴不同分辨率及传感器映射。正交模式空闲/失能轴按1ms采样，减少原25Hz读取下自由旋转时的跨半圈混叠。
- 新增`ENC?`诊断帧，回读当前方法、每轴CPR、原始计数、角度和计数器Ready状态。STATE增加EncType/C1/C2/C3，上位机兼容解析；正交界面显示“计数”，避免将计数器正常等同于模块在线。

## 固件与构建

无需改默认宏即可构建正交版：

```powershell
python .\Cubli-ST\build_firmware.py --encoder quad
```

输出：`Cubli-ST/MDK-ARM/CubeMX-quad/CubeMX.hex`，三轴默认1024 PPR→4096 CPR。烧录这个HEX才启用硬件正交；原`CubeMX/CubeMX.hex`仍为I2C版。

命令行也可以覆盖参数，等效于给所有源文件添加宏：

```powershell
python .\Cubli-ST\build_firmware.py --encoder quad --ppr 1024 --ppr-m2 1000 --ppr-m3 512
python .\Cubli-ST\build_firmware.py --encoder i2c
```

两种模式分别使用对象文件及链接响应文件，避免混用TIM5用途不同的目标文件。正交版每次构建覆盖`CubeMX-quad`目录；`build_config.json`记录本次编译宏。Keil界面直接构建时使用头文件宏，或在Target C/C++ Define中给整个工程设置`ENC_USE_HW_QUAD=1`；不要只对单个.c文件设置该宏。

## 板上确认方法

1. 确认模块处于AB输出模式，将三路A/B按表连接，共地并使用3.3V兼容电平，烧录正交版HEX。启动日志应显示硬件正交和`CPR=4096/4096/4096`；`STATE?`应有`EncType:1`。
2. 电机保持失能，发`ENC?`。手动缓慢转动各轴，上位机对应H角度应连续变化，其余轴不跟随。A/B换线会改变原始计数方向，之后的电角度对齐会识别编码器方向。
3. 在轴上做机械标记，手动约四分之一圈应对应约90°，默认原始计数差的绝对值约1024（按4096模数比较）。转一圈应走完一轮0～360°；如比例不符，修正对应PPR宏，不能靠修改电机极对数补偿。
4. 再对选中轴执行TEST/ALIGN。AB计数没有上电绝对零位，TIM2/5/8初始化后从0开始，每次重启或重新初始化都必须重新标定电角度。
5. 先低速闭环单轴验证正反转、速度回读和停止，再使用平衡模式。

`Ready:1`只代表F4计数器配置可用：AB静止、模块断线但输入保持固定电平，均可能没有任何计数变化，无法仅凭A/B判断区别。现有对齐位移验证和运行堵转保护可发现部分异常，但不是完整的编码器断线诊断。采样间隔跨越半机械圈后，只有单圈计数不能恢复遗漏的多圈位移；软件正常连续运行时使用快速采样，长时间暂停/断点后应停机重新标定。
